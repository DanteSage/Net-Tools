路由追踪工具 - 使用说明

一、路由追踪（基础模式）

显示数据包从本机到目标经过的所有路由节点。

  • 目标主机输入 IP 地址或域名，或点击预设按钮快速填充
  • 最大跳数限制追踪距离，默认 30 跳足够大多数场景
  • 超时每个跳点的等待时间，超过则标记为超时
  • DNS反向解析将 IP 解析为主机名，便于识别节点归属

二、MTR 模式（多轮统计）

多次重复追踪同一目标，统计丢包率和延迟分布。

  • 追踪轮数执行次数，轮数越多统计越精确
  • 丢包率 0%网络正常
  • 丢包率 1-20%可能存在拥塞
  • 丢包率 >20%网络问题严重，需排查

三、结果解读

  • 跳数数据包经过的路由器数量，越少越好
  • 延迟数据往返时间，越低越好（国内 <50ms 正常）
  • 抖动延迟波动程度，越低越稳定
  • 超时 (*)该跳点未响应，可能禁 ping 或故障

四、常见问题

  • 中间跳点超时但能到达终点？正常现象，部分路由器禁止 ICMP 响应
  • 延迟突然变高？关注哪个跳点开始变高，该节点可能是瓶颈
  • 为什么用 MTR？单次追踪可能偶然超时，MTR 多轮统计更准确

五、快捷键

  • 点击 预设按钮 快速填充常用目标
  • 点击右上角 月亮图标 切换深色/浅色主题
  • 点击 导出 保存追踪结果为文本文件

实现限制
  • 本工具未使用原始套接字，因此每跳的 RTT 是 本机到该跳 IP 的往返时间，非原版 Trippy 的"上一跳到本跳"段时延。
  • 路由发现阶段仍依赖系统 tracert / traceroute。Windows 上协议固定为 ICMP；TCP/UDP 仅影响后续逐跳探测方式。
  • UDP 探测在 Windows 上可能因系统对 ICMP port unreachable 的处理差异显示为持续超时；推荐使用 ICMP 或 TCP。
  • ASN/GeoIP 通过免费接口 ip-api.com 查询，每分钟 ≤ 45 次；私有地址不会发起请求。
  • 中间路由器若禁用 ICMP TTL Exceeded 响应，会显示为 "* * * 无响应"，属正常现象。
